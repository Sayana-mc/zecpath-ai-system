## Scope and evidence

The runnable application surface was traced through `src.main:app`, the FastAPI
routers and services, SQLite persistence, inline dashboard code in
`static/index.html`, root API tests, and the repository README. The primary ATS,
eligibility, transcript, speech-to-text, screening, report, fairness, Day 64,
and Day 65 modules were inspected to determine whether the root application
actually calls them. The full existing pytest suite and a real local browser
workflow were also run.

The checkout was already substantially modified before this work began,
including application code, tests, historical day modules, generated outputs,
and a deleted Day 30 file. Those changes were preserved; no reset, cleanup, or
checkout operation was used. This report does not represent a line-by-line
security or code review of every historical exercise.

## Application structure and data flow

| Layer | Current implementation |
|---|---|
| Startup | `uvicorn src.main:app`; FastAPI lifespan initializes SQLite and marks interrupted resume jobs failed. |
| Frontend | `static/index.html`, served by FastAPI at `/`; the UI and API are same-origin. |
| API | Root `src.api` routers under `/api/v1`; `/docs` is generated by FastAPI. |
| Persistence | SQLite, default `data/zecpath.sqlite3`, override with `ZECPATH_DB_PATH`; schema is created at connection time. |
| Resume flow | Upload → persisted processing-job row → FastAPI background task → PDF/DOCX/TXT text extraction → candidate resume text and job result. |
| Match flow | Saved candidate and opening → exact skill mentions/explicit profile skills → score plus evidence → persisted score → shortlist review suggestions. |
| Screening flow | Recruiter-entered question/answer → Day 25 keyword/regex answer analysis → persisted rule-based note and review flags. |
| Human decision | Recruiter manually updates application status. A score or shortlist suggestion does not update status. |

## Confirmed working surfaces

- The root API starts and its database-backed health check responds.
- Job and candidate CRUD, candidate status, resume extraction, score evidence,
  screening notes, and persisted shortlist suggestions have API coverage.
- PDF, DOCX, and TXT extraction and invalid/unreadable inputs are covered in
  root tests.
- Application and processing data persist in SQLite across application
  restarts; interrupted resume processing is marked failed.
- Authentication now supports a database-initialized first account without a
  hardcoded credential, salted PBKDF2-HMAC password hashes, HTTP-only
  SameSite=Strict session cookies, eight-hour expiry, revocation on logout,
  same-origin checks for cookie-authenticated writes, and persistent throttling
  after five failed login attempts.

## Release blockers and architectural limitations

- There is no versioned database migration framework, automated backup/
  restore process, or tested production database configuration.
- SQLite applicant data and extracted text are unencrypted. No tenant isolation,
  multiple recruiter accounts, or RBAC exists.
- Recruiter passwords are stored as salted PBKDF2 hashes in SQLite; no
  environment-based password mode is supported. Direct HTTP Basic
  authentication remains available for API clients and must be confined to
  localhost or protected by TLS.
- Candidate lists are unpaginated and return full extracted resume text.
- Resume processing runs as an in-process FastAPI background task; it is not a
  durable external worker queue, and duplicate-content detection is absent.
- Root API matching and screening use deterministic lexical/regex rules. No
  LLM is configured or called.
- OCR, full transcript integration, Day 26 scoring/report generation,
  independent fairness evaluation, consent/retention workflows, and
  production deployment are not implemented in the root app.
- No dependency vulnerability scan, load test, production deployment, or
  external security assessment was performed.

## Assessment

The root application is a runnable, synthetic-data local demo with a
meaningful recruiter workflow. It is not a fully integrated hiring system and
is not ready for staging or production use.
