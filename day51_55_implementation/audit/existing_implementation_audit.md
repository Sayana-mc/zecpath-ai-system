## 2. Partially Implemented Features & Discovered Bugs

| Area | Finding / Bug Observed in Inspection | Required Fix |
|---|---|---|
| **Day 51 Aggregation (`src/cross_round_scoring_engine.py` & `src/api.py`)** | `calculate_hiring_fit()` calls `database.save_cross_round_evaluation(record)` with `"hiring_fit_score"` key while `database.py` reads `"hiring_fit_percentage"` (persists `0.0` if called directly). Backend lacks per-stage status map (`COMPLETED`, `PENDING`, `NOT_STARTED`, `NOT_APPLICABLE`), minimum-required-stage threshold gate, configurable persistent role weights, idempotency fingerprint/duplicate check, recalculation reason history, and cross-tenant isolation. Existing `ROLE_ROUND_WEIGHTS` uses different Python weights (`10/10/10/30/40`) from Day 51 config (`10/10/15/35/30`); weight configuration must be configurable per role in DB. | Extend `cross_round_evaluations` schema, support configurable `role_weight_configurations`, add `stage_status`, `normalized_weights`, `calculation_status`, `min_required_stages`, `recalculation_reason`, and auto-recalculate trigger helper. |
| **Day 52 Decision Engine (`src/api.py`, `src/final_recommendation_engine.py`)** | `POST /api/v1/candidates/{id}/final-recommendation` in `src/api.py`: (1) ignores stored **mandatory eligibility evaluation** (`eligibility_evaluations`) even though high fit scores must never override a mandatory failure; (2) crashes with `DecisionInputError` if `integrity_flagged` or `behav_flagged` is `True` with an empty evidence list; (3) uses `cand.get("score") or 75.0` fallback when no cross-round evaluation exists instead of refusing to invent scores; (4) lacks per-role decision thresholds, structured `reason_codes`, `strengths`, `weaknesses`, `missing_evidence`, `confidence_methodology`, and a persistent `recommendation_decision_history` table. | Integrate eligibility check (mandatory failure -> `REJECTED` or `HOLD_REVIEW` per rule), fix empty-evidence safeguard, add per-role thresholds, persist explanation breakdown + `recommendation_decision_history`, and avoid fabricated `75.0` fallback. |
| **Day 53 Report Generator (`src/hiring_intelligence_report_generator.py`)** | (1) `render_report_html` line 419 multiplies `confidence * 100` when `final_recommendation.confidence` is already on a `0–100` scale (displays `9200%`!). (2) Machine test extraction reads `m_assign["test_id"]` & `sub.get("correctness_score")` instead of `sub.get("rubric_scores", {}).get("correctness")`. (3) Behavioral lookup checks `consent_recorded` & `signal_consistency_index` instead of `has_consent` & `consistency_index`. (4) **No PDF export endpoint** or PDF rendering exists in `src/` (`reportlab`/`weasyprint` are not installed; Chrome/Playwright IS installed or deterministic PDF byte generation is needed). | Normalize confidence formatting (`0–100` vs `0–1`), fix machine-test / behavioral field extraction, clearly show missing stages without inventing scores, include timestamp/version/confidentiality/weights table in HTML, and implement real PDF export (`/pdf` endpoints). |
| **Day 54 Optimization & Analytics (`src/api.py`, `src/optimization_engine.py`)** | `optimization_engine` is imported on line 172 of `src/api.py` and **never wired to any endpoint**. Threshold sweeps, labelled validation datasets, before/after comparison, and live measured latencies are not exposed via API or frontend. | Add `/api/v1/optimization/*` endpoints reading actual DB evaluations + labelled synthetic validation dataset, persist `optimization_runs` for genuine before/after measurements, enforce safe caching/query efficiency while logging response timings. |
| **Day 55 Governance, RBAC & Consent (`src/auth.py`, `src/api.py`, `src/database.py`)** | (1) `require_recruiter` returns a `str` username while `monitoring/*` endpoints annotate `recruiter: dict = Depends(require_recruiter)` and call `recruiter.get("username")` (runtime `AttributeError`!). (2) `recruiter_accounts` has no `role` or `tenant_id` column. (3) `openings` and `candidates` have no `tenant_id` column. (4) `security_governance.check_permission` is never enforced in any FastAPI route. (5) No persistent SQLite `candidate_consents` ledger or `retention_policies` table/API exists; file-based `ConsentRegistry` is isolated in `day55_security_ai_governance/`. (6) Audit logging is missing for score creation/recalculation, candidate access, recommendation creation, report HTML/PDF export, and consent changes. | Migrate `recruiter_accounts` (`role`, `tenant_id`), `openings` (`tenant_id`), `candidates` (`tenant_id`); add `require_recruiter_context` + `require_permission(action)` dependency; fix `monitoring` endpoints; add `candidate_consents`, `retention_policies`, and `/api/v1/governance/*` + `/api/v1/candidates/{id}/consent` APIs; enforce tenant isolation + audit events. |
| **Frontend UI (`static/index.html`)** | Only ATS + small per-row `<details>` stubs exist. No dedicated Cross-Round Evaluation panel, Recommendation Review panel (with confidence breakdown, strengths/weaknesses/risks, approve/override/reject buttons, and decision history), full Hiring Intelligence Report modal/view (with 14 sections + HTML/PDF export), Optimization Analytics dashboard, or Security & Governance Audit view. | Add clean navigation tabs/panels in `#workspace` in `static/index.html` for all 5 Days (51–55) backed 100% by real API calls, preserving existing ATS layout & `test_api.py` assertions. |

## 3. Dependency Graph (Days 51–55)

1. **Day 55 Core Auth/Tenant Foundation (`auth.py`, `database.py`)** -> Required by Days 51–55 routes so every calculation, recommendation, report export, and audit query enforces RBAC, logs `actor_id` accurately, and isolates tenants.
2. **Day 51 Cross-Round Aggregation Engine** -> Consumes Stage 1–5 DB records -> Produces persisted `cross_round_evaluations` -> Feeds **Day 52 Decision AI** & **Day 53 Reports**.
3. **Day 52 Final Recommendation AI** -> Consumes Day 51 evaluation + Eligibility + Behavioral/Integrity flags -> Produces `final_recommendations` & `recommendation_decision_history` -> Feeds **Day 53 Reports**.
4. **Day 53 Hiring Intelligence Report Generator** -> Consumes candidate + job + Stages 1–5 + Day 51 + Day 52 -> Exports JSON/Markdown/HTML/PDF + triggers `HIRING_REPORT_EXPORTED` / `HIRING_REPORT_GENERATED` audit events.
5. **Day 54 Optimization & Refinement** -> Evaluates synthetic ground-truth benchmark + live DB evaluations -> Exposes metrics, threshold comparisons, ambiguity detection, and query timing analytics.
